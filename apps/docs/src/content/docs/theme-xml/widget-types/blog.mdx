The `Blog` widget carries the content of every page. On the homepage, a label page, a search or an archive it receives a list of posts; on a post or a static page it receives that one item, with its comments. Google calls it "the central part of any blog, and the most complex". <BloggerSource kind="official" />

Its data is the richest of all widget types, and its built-in markup is split into dozens of small includables. A theme can keep them, override a few, or ignore them and write its own `main`.

## Quick example

A complete widget for a responsive theme: cards with a snippet on list pages, the full post with its labels on a post page, a pager, and a message when there is nothing to show.

<CodeTabs>

```xml title="theme.xml" {21}
<b:section id='theme_section_main' name='Main' showaddelement='false'>
  <b:widget id='Blog1' locked='true' title='Blog Posts' type='Blog' version='2' visible='true'>
    <b:includable id='main' var='this'>
      <b:if cond='data:posts.empty'>
        <p class='no-posts'><data:messages.theresNothingHere/></p>
      </b:if>
      <b:loop values='data:posts' var='post'>
        <article class='entry' expr:data-id='data:post.id'>
          <b:class cond='data:view.isSingleItem' name='entry-full'/>
          <b:tag class='entry-title' expr:name='data:view.isSingleItem ? "h1" : "h2"'>
            <b:tag cond='data:view.isMultipleItems' expr:href='data:post.url.canonical' name='a'>
              <data:post.title/>
            </b:tag>
          </b:tag>
          <time expr:datetime='data:post.date.iso8601'><b:eval expr='format(data:post.date, "MMM d, yyyy")'/></time>
          <b:if cond='data:view.isSingleItem'>
            <div class='entry-body'><data:post.body/></div>
            <b:loop values='data:post.labels' var='label'>
              <a expr:href='data:label.url.canonical' rel='tag'><data:label.name/></a>
            </b:loop>
            <b:include cond='data:post.allowComments' data='post' name='commentPicker'/>
          <b:else/>
            <p class='entry-snippet'><b:eval expr='snippet(data:post.body, { length: 150, links: false })'/></p>
          </b:if>
        </article>
      </b:loop>
      <b:if cond='data:view.isMultipleItems'>
        <nav class='pager'>
          <b:if cond='data:newerPageUrl'><a expr:href='data:newerPageUrl' rel='prev'><data:messages.newerPosts/></a></b:if>
          <b:if cond='data:olderPageUrl'><a expr:href='data:olderPageUrl' rel='next'><data:messages.olderPosts/></a></b:if>
        </nav>
      </b:if>
    </b:includable>
  </b:widget>
</b:section>
```

```html title="Rendered, on the homepage"
<div class='widget Blog' data-version='2' id='Blog1'>
  <article class='entry' data-id='4417296153873652218'>
    <h2 class='entry-title'><a href='https://example.blogspot.com/2026/10/release-notes.html'>Release notes</a></h2>
    <time datetime='2026-10-12T08:15:00+05:30'>Oct 12, 2026</time>
    <p class='entry-snippet'>What changed in this release, in a few lines of plain text…</p>
  </article>
  <nav class='pager'>
    <a href='https://example.blogspot.com/search?updated-max=2026-10-01T09:00:00%2B05:30&amp;max-results=7' rel='next'>Older Posts</a>
  </nav>
</div>
```

</CodeTabs>

- `commentPicker` is not declared in this widget. Blogger renders its built-in version, and the built-in comment includables under it. <BloggerSource kind="observed" /> To restyle the comments, declare `commentPicker` and what it calls, see [Comments](#comments).
- On the 404 page `data:posts` is empty, so only the message renders.

## Placement and limits

|          |                                                                                                                                                   |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| Pages    | All of them: lists of posts, posts, static pages, and the 404 page with an empty `data:posts`                                                     |
| Section  | Its own section in Blogger's themes, with `showaddelement='false'`: `main` in classic themes, `page_body` in the responsive ones                  |
| Id       | `Blog1` in Blogger's themes. Hand-written themes use any digits, such as `Blog01` or `Blog010`                                                    |
| Locked   | Always, in Blogger's themes, so it can not be removed in the Layout editor, see [`locked`](../layout/widgets.mdx#locked)                          |
| Per blog | At least 2; a higher maximum is not confirmed, see [Widgets per type](../reference/limits.mdx#widgets-per-type) <BloggerSource kind="observed" /> |
| Versions | 1 in classic themes, 2 in responsive themes                                                                                                       |
| XML      | Editable, except in the classic mobile theme and Dynamic Views, whose posts are rendered by Blogger's script <BloggerSource kind="observed" />    |

- **More than one, or none.** A theme can hold several Blog widgets: one in a head section that prints meta tags (see [Widgets in the head](../guides/head-and-seo.mdx#widgets-in-the-head)), one in a hidden section that prints the posts as JSON for scripts, and the visible one. <BloggerSource kind="observed" /> A theme with no Blog widget saves, see [Widgets per type](../reference/limits.mdx#widgets-per-type).
- **Neighbors.** Blogger's responsive themes place a `FeaturedPost` widget (homepage only) and a `PopularPosts` widget (post pages only) in the same section, and the Blog widget's `main` drops the featured post from its list. See [Hiding posts from the list](#hiding-posts-from-the-list). <BloggerSource kind="observed" />
- **Shared settings.** The Blog widget's byline settings also decide the bylines of the [FeaturedPost](./featured-post.mdx) and [PopularPosts](./popular-posts.mdx) widgets.

### Texts

The texts printed before or after a byline item. They reach the markup as the `label` of the byline item, and as data of the same name in version 1.

| Setting             | English default | Printed                 | Source                            |
| ------------------- | --------------- | ----------------------- | --------------------------------- |
| `authorLabel`       | `By`            | before the author       | <BloggerSource kind="observed" /> |
| `timestampLabel`    | `at`            | before the date         | <BloggerSource kind="observed" /> |
| `commentLabel`      | `comments`      | after the comment count | <BloggerSource kind="observed" /> |
| `postLabelsLabel`   | `Labels:`       | before the labels       | <BloggerSource kind="observed" /> |
| `postLocationLabel` | `Location:`     | before the location     | <BloggerSource kind="observed" /> |

An empty setting, `<b:widget-setting name='timestampLabel'/>`, gives an empty label. Blogger's responsive themes install some of them empty, or as `-`. A label is 50 characters at most: a longer one is refused "Must be at most 50 characters" when the theme is saved. <BloggerSource kind="observed" />

### Retired settings

| Setting                                                                                                        | Was                                                                       | Source                                                                |
| -------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| `showBacklinks`, `backlinksLabel`                                                                              | Backlinks                                                                 | <BloggerSource kind="deprecated" />                                   |
| `showReactions`, `reactionsLabel`                                                                              | Reactions                                                                 | <BloggerSource kind="deprecated" />                                   |
| `style.unittype`, `style.bgcolor`, `style.bordercolor`, `style.linkcolor`, `style.textcolor`, `style.urlcolor` | Colors of text ads (`TextAndImage`, `#ffffff`…). Still written by Blogger | <BloggerSource kind="deprecated" />                                   |
| `disableGooglePlusShare`                                                                                       | The Google+ share button. Dropped silently when the theme is saved        | <BloggerSource kind="observed" /> <BloggerSource kind="deprecated" /> |

When the theme is saved: <BloggerSource kind="observed" />

- A Blog widget written with no settings gets the title `Blog Posts` and `showDateHeader` `false`, `showShareButtons` `false`, `showCommentLink` `true`, `showAuthor` `true`, `style.unittype` `TextAndImage`, `reactionsLabel` empty, `showAuthorProfile` `false`, `style.layout` `1x1`, `showLabels` `true`, `showLocation` `true`, `showTimestamp` `true`, `postsPerAd` `1`, `showBacklinks` `false`, `showInlineAds` `false` and `showReactions` `false`. Missing settings of a widget written with some get the same defaults.
- An unknown setting name, such as `x` or `disableGooglePlusShare`, is dropped without a message. Every other type refuses it.
- `style.layout` refuses `2x2` or `x` with "Unknown ad layout", and `style.unittype` a wrong value with "Unknown ad unit type", case-sensitive. An empty value gives the default.

Three options of the Layout editor have no setting in the theme file: the number of posts on the main page, the text of the jump link (read as `data:blog.jumpLinkMessage`), and "Show email post links" (read through `data:post.emailPostUrl`). The order of the byline items is not a setting either; it is read through the [bylines](#bylines).

## Widget data

Inside the widget, the data is read as `data:name`. With `var='this'` (responsive themes) or `var='top'` (classic themes) on `main`, it can also be read as `data:this.name` from includables where a local `name` hides it: `data:this.messages.blogComment`, `data:top.showAuthor`.

The global data is available too: [`data:blog`](../data/blog.mdx), [`data:view`](../data/view.mdx), [`data:messages`](../data/messages.mdx), [`data:widgets`](../data/widgets.mdx).

### From other widgets

In responsive themes, `data:widgets.Blog` can be read from any widget, or from outside widgets: each entry has a light copy of the posts (`id`, `title`, `featuredImage`, `showInlineAds`) and the byline options, `headerByline`, `footerBylines` and `allBylineItems`. It is empty when the widget is missing, so `data:widgets.Blog.first.allBylineItems.timestamp` reads nothing rather than failing. See [Blog entries](../data/widgets.mdx#blog-entries) and [Bylines](#bylines).

## Posts

`data:posts` holds every post of a list page, one post on a post page, one page on a static page, and nothing on the 404 page. On a list page, `body` stops at the jump break. Which fields each version has, version 1 against version 2, is on [Versions](../data/post.mdx#versions) and [Content](../data/post.mdx#content); the comment fields are on [Comment data](../data/comments.mdx).

### Hiding posts from the list

`data:posts` can be redefined with [`b:with`](../tags/variables.mdx) before the loop, for example to drop from the homepage list the post a FeaturedPost widget already shows. Blogger's responsive themes do this, then call `super.main`. The pattern and its caveats are on [Do not show the post twice on the homepage](./featured-post.mdx#do-not-show-the-post-twice-on-the-homepage).

## Bylines

The bylines are the small items around a post: author, date, comment count, labels, location, share buttons, email link. In the Layout editor, the blog owner turns them on and arranges them in a header line and up to three footer lines. Version 2 widgets read that arrangement from `data:widgets.Blog`:

| Data             | Holds                                                        |
| ---------------- | ------------------------------------------------------------ |
| `headerByline`   | The header line, with `regionName` and `items`               |
| `footerBylines`  | Up to three footer lines, each with `regionName` and `items` |
| `allBylineItems` | Every item turned on, in any line                            |

Each item has a `name` and a `label`, in the order set in the Layout editor; a line and `allBylineItems` hold 7 items at most. An item can also be read by name: `allBylineItems.share` is the share item when it is on, and nothing otherwise. `labels` is the name of an item, `label` the text of any item. <BloggerSource kind="observed" /> The fields are on [Blog entries](../data/widgets.mdx#blog-entries).

| `name`      | Item                | Built-in includable | Rendered when             | `label` in English |
| ----------- | ------------------- | ------------------- | ------------------------- | ------------------ |
| `author`    | The author          | `postAuthor`        | always                    | `By`               |
| `timestamp` | The date            | `postTimestamp`     | not on a static page      | `at`               |
| `comments`  | The comment link    | `postCommentsLink`  | `data:post.allowComments` | `comments`         |
| `labels`    | The labels          | `postLabels`        | the post has labels       | `Labels:`          |
| `location`  | The location        | `postLocation`      | the post has a location   | `Location:`        |
| `share`     | The share buttons   | `postShareButtons`  | `data:post.shareUrl`      | empty              |
| `icons`     | The email-post link | `emailPostIcon`     | `data:post.emailPostUrl`  | empty              |

The `label` of an item is the text of its setting, `authorLabel` for `author` and so on; Blogger's 2017 themes install other defaults, such as `-` for the timestamp. <BloggerSource kind="observed" /> No `reactions` item exists: reactions are retired and `postReactions` has rendered nothing since 2021. <BloggerSource kind="observed" />

### Reading the switches

A theme that writes its own post markup can still honor the Layout editor by testing the items by name:

```xml
<div class='entry-info'>
  <b:if cond='data:widgets.Blog.first.allBylineItems.author'>
    <span class='entry-author'><data:widgets.Blog.first.allBylineItems.author.label/> <data:post.author.name/></span>
  </b:if>
  <b:if cond='data:widgets.Blog.first.allBylineItems.timestamp'>
    <time expr:datetime='data:post.date.iso8601'><data:post.date/></time>
  </b:if>
  <b:if cond='data:widgets.Blog.first.allBylineItems.comments and data:post.allowComments'>
    <a expr:href='data:post.url.canonical fragment "comments"'><data:post.numberOfComments/></a>
  </b:if>
</div>
```

### Lines and regions

To keep the order of the items as well, loop over the lines and dispatch on `name`. The built-in markup does this with three includables: `headerByline` and `footerBylines` render the lines, `bylineRegion` loops over the items of a line, and `bylineByName` is a `b:switch` on `data:byline.name` that includes the item's includable. A theme can reuse them:

```xml
<b:loop index='i' values='data:widgets.Blog.first.footerBylines' var='line'>
  <b:if cond='not data:line.items.empty'>
    <div expr:class='"entry-footer-" + (data:i + 1)'>
      <b:include data='line.items' name='bylineRegion'/>
    </div>
  </b:if>
</b:loop>
```

- `headerByline` wraps its line in `div.post-header > div.post-header-line-1`; `footerBylines` writes one `div.post-footer-line.post-footer-line-N` per line.
- The built-in includables set a variable `regionName` to `header-1`, or `footer-1` to `footer-3`, used in the id of the share menu. The `regionName` of the data has no hyphen: `header1`, `footer1`. <BloggerSource kind="observed" />
- A line can come out empty when its items are on but render nothing on that page, labels hidden on list pages for example. <BloggerSource kind="observed" />
- The item includables print the label with `<data:byline.label/>`.
- Two Common includables force items whatever the settings: `headerBylineOverride` takes `items`, a list of names, and `footerBylinesOverride` takes `items`, a list of lines. <BloggerSource kind="observed" />

```xml
<b:include data='{ items: ["author", "timestamp"] }' name='headerBylineOverride'/>
<b:include data='{ items: [["labels"], ["share", "comments"]] }' name='footerBylinesOverride'/>
```

### Version 1

Version 1 has no byline data. Its `post` includable places every item at a fixed spot, in `post-footer-line-1` to `post-footer-line-3`, each in a `b:if` on a switch such as `data:top.showAuthor`. Moving an item in the Layout editor does not move it in a version 1 theme that was edited by hand, since the place is in the markup.

## Sharing

The share buttons use the global `data:blog.sharing.platforms`, in this order:

| `key`       | `target`    | `name` in English |
| ----------- | ----------- | ----------------- |
| `link`      | empty       | Get link          |
| `facebook`  | `facebook`  | Facebook          |
| `blogThis`  | `blog`      | BlogThis!         |
| `twitter`   | `twitter`   | X                 |
| `pinterest` | `pinterest` | Pinterest         |
| `email`     | `email`     | Email             |

Each platform also has a `shareMessage`, such as "Share to Facebook". A share link is `data:post.shareUrl` followed by `&target=` and the `target` of the platform, the form Blogger's own share menu builds. With the empty target of `link`, the URL ends with `&target=`. <BloggerSource kind="observed" />

```xml
<ul class='share'>
  <b:loop values='data:blog.sharing.platforms filter (p => p.key not in ["link", "blogThis"])' var='platform'>
    <li>
      <a expr:aria-label='data:platform.shareMessage' expr:href='data:post.shareUrl + "&amp;target=" + data:platform.target' rel='nofollow noopener' target='_blank'>
        <data:platform.name/>
      </a>
    </li>
  </b:loop>
</ul>
```

## Pagination

### Pages of posts

On a list page, `newerPageUrl` and `olderPageUrl` lead to the neighboring pages of the list. On a post page they lead to the next newer and older posts. Each is missing when there is nothing in that direction.

A pager with a Home link in the middle, written with [`b:tag`](../tags/dynamic-tags.mdx) so that a missing direction renders as a disabled `div`:

```xml
<b:includable id='postPagination'>
  <nav class='pager' id='blog-pager'>
    <b:tag class='pager-newer' expr:name='data:newerPageUrl ? "a" : "div"'>
      <b:class cond='not data:newerPageUrl' name='disabled'/>
      <b:attr cond='data:newerPageUrl' expr:value='data:newerPageUrl' name='href'/>
      <data:messages.newerPosts/>
    </b:tag>
    <b:if cond='data:view.url != data:blog.homepageUrl'>
      <a class='pager-home' expr:href='data:blog.homepageUrl.canonical'><data:messages.home/></a>
    </b:if>
    <b:tag class='pager-older' expr:name='data:olderPageUrl ? "a" : "div"'>
      <b:class cond='not data:olderPageUrl' name='disabled'/>
      <b:attr cond='data:olderPageUrl' expr:value='data:olderPageUrl' name='href'/>
      <data:messages.olderPosts/>
    </b:tag>
  </nav>
</b:includable>
```

Scripts that load the next page in place need the same two URLs, printed as JSON, see [The pager for scripts](../guides/posts-and-pagination.mdx#the-pager-for-scripts).

The built-in pager:

| Includable         | Renders                                                                                               | Text                                      |
| ------------------ | ----------------------------------------------------------------------------------------------------- | ----------------------------------------- |
| `postPagination`   | `div.blog-pager#blog-pager` with the three links below. The built-in `main` includes it on list pages |                                           |
| `previousPageLink` | `a.blog-pager-newer-link` to `data:newerPageUrl`                                                      | `data:messages.newerPosts`, "Newer Posts" |
| `nextPageLink`     | `a.blog-pager-older-link` to `data:olderPageUrl`                                                      | `data:messages.olderPosts`, "Older Posts" |
| `homePageLink`     | `a.home-link` to `data:blog.homepageUrl`, except on the homepage                                      | `data:messages.home`, "Home"              |

Most of Blogger's responsive themes empty `previousPageLink` and `homePageLink` and turn `nextPageLink` into a single "More posts" button with `data:messages.morePosts`. `data:messages.loadMorePosts`, "Load more posts", is used by no built-in includable.

In version 1, `nextprev` renders `#blog-pager` with `#blog-pager-newer-link` and `#blog-pager-older-link`, titled with `data:newerPageTitle` and `data:olderPageTitle`, an `a.home-link` with `data:homeMsg`, and the link to the mobile view. `mobile-nextprev` is the pager of the classic mobile view.

### Pages of comments

A post with more than 200 comments has comment pages. The built-in `comments` includable renders their pager, in both versions. The paging fields and an example are on [Comment paging](../data/comments.mdx#comment-paging).

## Comments

Comments render on post and static pages only. The built-in entry point is `commentPicker` (`comment_picker` in version 1). It chooses between two includables:

- **`threadedComments`** when `data:post.showThreadedComments` is `true`. Blogger writes the comments as HTML, `data:post.commentHtml`, with their replies, and its script drives the reply form. Its conditions are on [Threads](../data/comments.mdx#threads).
- **`comments`** otherwise. The theme loops over `data:post.comments` and renders each one with `commentItem`.

A theme may also replace `threadedComments` with its own loop over `data:post.comments`, building the threads from `inReplyTo` and loading the form on demand: see [Threads](../guides/comments.mdx#threads) and [The comment form](../guides/comments.mdx#the-comment-form) for the how-to, and [Pages of comments](#pages-of-comments) for posts with more than 200 comments. The fields of a comment are in [Comment data](../data/comments.mdx).

## Inline ads

When `showInlineAds` is on, Blogger flags every `postsPerAd`-th post with `data:post.includeAd` and numbers them with `data:post.adNumber`. The ad itself is `data:adCode`, or an AdSense unit built from `data:adClientId`. In the theme preview, Blogger's markup shows a placeholder instead of a live ad:

```xml {2-3}
<b:includable id='inlineAd' var='post'>
  <b:if cond='data:view.isPreview'>
    <div class='inline-ad-placeholder'><data:messages.adsGoHere/></div>
  <b:elseif cond='data:this.adCode != ""'/>
    <div class='inline-ad'><data:this.adCode/></div>
  <b:elseif cond='data:this.adClientId or data:blog.adsenseClientId'/>
    <div class='inline-ad'><b:include name='defaultAdUnit'/></div>
  </b:if>
</b:includable>
```

`defaultAdUnit` renders `ins.adsbygoogle` for `data:adClientId ?: data:blog.adsenseClientId`, and its push script. It reads an optional `style` for the `ins` element; Blogger's themes pass a non-empty CSS comment with `b:with` to clear it, then call `super.defaultAdUnit`. It is shared with the [AdSense](./adsense.mdx) widget.

│  │  ├─ postMeta → postMetadataJSON

### Turning parts off

A theme that writes its own markup can declare every built-in includable it does not use as a stub. The widget then holds none of Blogger's markup, and an include of one of those ids renders nothing instead of falling back to the built-in version:

```xml
<b:includable id='feedLinks'><!--[ removed ]--></b:includable>
<b:includable id='postReactions'><!--[ removed ]--></b:includable>
<b:includable id='tooltipCss'/>
```

An empty or self-closed includable renders nothing. The full list of ids to stub for a version 2 Blog widget is every id in the tables above.

- `inlineAd` stops after three ads, using `data:post.adNumber`.
- `defaultAdUnit` clears the ad style, then calls `super.defaultAdUnit`.
- `feedLinks` renders nothing.
- `previousPageLink` and `homePageLink` render nothing, and `nextPageLink` becomes a "More posts" button.
- `postJumpLink` renders nothing in Contempo, which moves the link into its `postFooter`; Emporio shows no jump link at all.
- `postLabels` shows the labels only on a post page of the Blog widget, then calls `super.postLabels`.
- `postShareButtons` renders nothing in Contempo, which places the share buttons through `maybeAddShareButtons` instead.
- `headerByline` and `footerBylines` add share buttons, or force items with the override includables.

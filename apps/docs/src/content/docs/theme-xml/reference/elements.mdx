This page is an inventory. Each element links to the page that explains it, with examples and sources. Here are the facts that apply across elements: which ones exist, where each may go, which must be empty, and how their attributes are read.

## The `b:` elements

Blogger knows a fixed set of `b:` elements, the ones in the tables below. An unknown name in the `b:` namespace, a misspelled `<b:includeable>` for example, saves and does nothing, and so does an attribute Blogger does not read on a known element, see [Blogger's elements](../basics/saving.mdx#bloggers-elements). <BloggerSource kind="observed" />

The "Empty" column says what the element may contain:

- **Required**: write the element self-closed. Content saves, but is dropped or ignored when rendered; in `<b:include>`, content other than whitespace is a [markup error](../basics/saving.mdx#markup-errors). See [Saving a theme](../basics/saving.mdx#empty-elements).
- **Allowed**: the element may have content or none. Blogger saves an element with nothing inside as self-closed, `<b:if cond='true'/>`.

## How attributes are read

The attributes of `b:` elements are of three kinds.

**Expressions.** The value is an [expression](../expressions/index.mdx), evaluated when the page is rendered: `cond='data:view.isPost'`, `values='data:posts'`. Blogger does not read it when saving: an expression that does not parse saves, and fails only when a page reaches it. <BloggerSource kind="observed" />

**Text.** The value is used as written: `name='postTitle'`, `value='2px'`. The `expr:` prefix computes it instead: `expr:name='data:platform.key + "Icon"'`. <BloggerSource kind="observed" />

**No `expr:` form.** Some attributes are literal only, or their `expr:` form is deleted or not rendered. Blogger reads the `id` of `<b:section>`, and the `id` and `type` of `<b:widget>`, when the theme is saved, to build the list of sections and widgets. The last column of the table lists them, and [`expr:` forms of attributes](../basics/saving.mdx#expr-forms-of-attributes) says what saving and rendering do with each. <BloggerSource kind="observed" />

### `ATTR` and `expr:ATTR` together

When an element has both `ATTR` and `expr:ATTR`, the `expr:` one wins, on HTML elements and on `b:` elements alike, and Blogger keeps both in the file. The exceptions, such as `<b:widget>`, whose `expr:` attributes are deleted, are in [`expr:` forms of attributes](../basics/saving.mdx#expr-forms-of-attributes); see also [`ATTR` and `expr:ATTR` together](../tags/attributes.mdx#attr-and-exprattr-together). <BloggerSource kind="observed" />

### `expr:` on an expression attribute

An `expr:` prefix on an attribute that is already an expression evaluates twice: the first result is read as an expression in turn. [Dynamic paths](../expressions/data-paths.mdx#dynamic-paths) shows how a theme uses it on text typed by the blog owner, and how to check that text first. <BloggerSource kind="observed" />

## Other uses of `expr:`

On HTML elements, `expr:` works on any attribute, including `data-*` and `aria-*` ones. These are from production themes: <BloggerSource kind="observed" />

```xml
<b:include expr:name='data:platform.key + "Icon"'/>
<b:class expr:name='data:display + "-list"'/>
<b:attr cond='data:sizes' expr:value='data:sizes' name='sizes'/>
<b:tag expr:name='data:link ? "a" : "span"'>…</b:tag>
<span class='views' expr:data-id='data:post.id'/>
```

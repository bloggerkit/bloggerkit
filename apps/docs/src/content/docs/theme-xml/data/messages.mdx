`data:messages` is a dictionary of short interface texts, "Home", "Older Posts", "Post a Comment", already translated into the language of the blog. A theme that prints them instead of writing its own words speaks the language of every blog it is installed on, with nothing to configure.

<CodeTabs>

```xml title="Links between pages of posts"
<nav class='blog-pager'>
  <b:if cond='data:newerPageUrl'>
    <a class='newer' expr:href='data:newerPageUrl' rel='prev'><data:messages.newerPosts/></a>
  </b:if>
  <a class='home' expr:href='data:blog.homepageUrl'><data:messages.home/></a>
  <b:if cond='data:olderPageUrl'>
    <a class='older' expr:href='data:olderPageUrl' rel='next'><data:messages.olderPosts/></a>
  </b:if>
</nav>
```

```html title="Rendered on the second page, English blog"
<nav class='blog-pager'>
  <a class='newer' href='https://example.blogspot.com/search?…' rel='prev'>Newer Posts</a>
  <a class='home' href='https://example.blogspot.com/'>Home</a>
  <a class='older' href='https://example.blogspot.com/search?updated-max=2026-04-11T08:15:00%2B01:00&amp;max-results=7' rel='next'>Older Posts</a>
</nav>
```

</CodeTabs>

`data:messages` is global: it can be read anywhere under `<html>`, but not inside `<![CDATA[ ]]>`. Google does not document it. This page lists **95 keys**. <BloggerSource kind="observed" />

## Printing a message

A message prints like any data, with a data tag or `<b:eval>`, or through [`<b:message>`](../tags/messages.mdx#output), which is required for messages that take parameters. The `name` of `<b:message>` is the path without `data:`, `<b:message name='messages.share'/>`. The language is the language of the blog, or the one given with `?hl=` in the URL, see [`data:blog.locale`](./blog.mdx#databloglocale).

A message without parameters reads like a string. Themes write `.escaped` on it in an attribute and `.jsonEscaped` in JSON: <BloggerSource kind="observed" />

```xml {2}
<button class='share-button' expr:aria-label='data:messages.share.escaped' type='button'/>
<script id='messages' type='application/json'>{"copied":"<data:messages.linkCopiedToClipboard.jsonEscaped/>","loading":"<data:messages.loading.jsonEscaped/>"}</script>
```

The second line hands translated texts to client scripts, which can not read `data:messages` themselves. A theme can write several dozen keys into such a block. <BloggerSource kind="observed" /> Whether the escapes change the text of a message is not confirmed, and a message with parameters, printed by `<b:message>`, can not take them.

## Messages with parameters

Ten messages have a slot for a value, the name of an author or a number. They are printed with `<b:message>`, one `<b:param>` per value:

<CodeTabs>

```xml title="theme.xml"
<b:message name='messages.numberOfComments'>
  <b:param expr:value='data:post.numberOfComments' name='numComments'/>
</b:message>
```

```html title="Rendered with 3 comments"
3 comments
```

</CodeTabs>

| Key                    | Parameters                | What they are                                                       | Seen in Blogger's themes | Source                            |
| ---------------------- | ------------------------- | ------------------------------------------------------------------- | ------------------------ | --------------------------------- |
| `authorSaid`           | `authorName`              | The name of the commenter                                           | yes                      | <BloggerSource kind="observed" /> |
| `authorSaidWithLink`   | `authorName`, `authorUrl` | The name and address of the commenter                               | yes                      | <BloggerSource kind="observed" /> |
| `byAuthor`             | `authorName`              | The name of the author of the post                                  | no                       | <BloggerSource kind="observed" /> |
| `byAuthorLink`         | `authorName`, `authorUrl` | The name and profile of the author of the post                      | no                       | <BloggerSource kind="observed" /> |
| `numberOfComments`     | `numComments`             | A count: `No comments` for 0, `1 comment` for 1, `3 comments` for 3 | yes                      | <BloggerSource kind="observed" /> |
| `postedByAuthor`       | `authorName`              | The name of the author of the post                                  | no                       | <BloggerSource kind="observed" /> |
| `postedByAuthorLink`   | two, names not confirmed  | The name, then the profile, of the author of the post               | no                       | <BloggerSource kind="observed" /> |
| `poweredByBloggerLink` | one, name not confirmed   | The address of Blogger, `data:blog.bloggerUrl`                      | no                       | <BloggerSource kind="observed" /> |
| `templateImagesBy`     | one, name not confirmed   | The name of the author of the theme images                          | yes                      | <BloggerSource kind="observed" /> |
| `templateImagesByLink` | two, names not confirmed  | The address, then the name, of the author of the theme images       | yes                      | <BloggerSource kind="observed" /> |

Blogger's themes confirm the parameter names of `authorSaid`, `authorSaidWithLink` and `numberOfComments`, and a test confirmed `authorName` for `postedByAuthor`. For the others, the names Blogger expects are not confirmed. <BloggerSource kind="observed" /> A `<b:param>` without a `name` also fills the next slot, and some of the linked messages failed in tests: see [Named and positional parameters](../tags/messages.mdx#named-and-positional-parameters).

`numberOfComments` picks the singular or plural form itself. Test the count only to show something else for zero, such as `data:messages.postAComment`.

## Notes on the keys

- **Retired keys.** `edit`, `emailAddress`, `euCookieResponsibility` and `getEmailNotifications` are no longer used by Blogger, and `euCookieNotice` is not used by the 2017 themes. They still return their text. `deleteComment` is still printed by the delete icon of the 2017 themes.
- **Two cookie notices.** `euCookieNotice` and `euCookieResponsibility` are the old texts, the `2018` keys the current ones. `euCookieNoticeCloseButton` and `gotIt` both give "Got it".
- **`widget`** gives "Gadget", the word of the Blogger dashboard.
- **`shareOtherApps` and `shareToOtherApps`** appear in the hidden "other apps" share button of Blogger's themes. Their text is not confirmed.
- **Outside the 95.** Some classic themes read `data:messages.moveToPage`, and a key `widgetNotAvailableOnHttps` exists. The text of either is not confirmed.

## Texts the theme defines

The dictionary is fixed: a theme can not add a key to it. For its own words, a theme can declare string variables in its skin, one per text, and the owner translates them in Edit HTML, in the `value` of each variable. A `string` variable gets no form in the Theme Designer, see [Types](../styles/theme-designer.mdx#types): <BloggerSource kind="observed" />

```xml
<b:skin><![CDATA[/*
<Variable default="" description="For: Reply" name="m.reply" type="string" value="Reply"/>
<Variable default="" description="For: New!" name="m.new" type="string" value="New!"/>
*/]]></b:skin>

<button class='reply-button' expr:aria-label='data:skin.vars.m_reply' type='button'><data:skin.vars.m_reply/></button>
```

Use `data:messages` wherever a key fits, since it follows the language of each blog by itself, and variables for the rest. See [data:skin](./skin.mdx).

## Widget messages

Texts that the owner writes, or that belong to one widget, are widget data rather than keys of the dictionary:

- **The Blog widget, version 2,** has its own `data:messages` with one member, `blogComment`: the note written above the comment form in Settings > Comments. Inside the Blog widget, `data:messages` still gives the global texts in Blogger's themes, and the widget's note is read through the name of the widget data, `data:this.messages.blogComment`. How the two are combined is not confirmed.
- **Version 1 widgets** receive their texts as widget data, such as `data:homeMsg` or `data:postCommentMsg` in the Blog widget and `data:viewProfileMsg` in the Profile widget. Version 2 replaced most of them with global keys:

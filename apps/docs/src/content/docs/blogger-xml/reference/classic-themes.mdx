Before the themes of 2017, Blogger shipped other generations of themes. They still work, many blogs still run them, and their files use tags that a layouts version 3 theme never needs. This page explains them, so that an old theme can be read and maintained. The rest of the guide is about layouts version 3, and says when something also applies here.

| Generation        | Year | `<html>`                                          | Widgets                 | Themes of Blogger                                                 |
| ----------------- | ---- | ------------------------------------------------- | ----------------------- | ----------------------------------------------------------------- |
| Layouts version 1 | 2006 | no version                                        | version 1               | The first layouts themes                                          |
| Layouts version 2 | 2010 | `b:version='2'`                                   | version 1               | Simple, Picture Window, Awesome Inc., Watermark, Ethereal, Travel |
| Dynamic Views     | 2011 | `b:dynamicViews='true' b:version='2'`             | version 1, not rendered | Classic, Flipcard, Magazine, Mosaic, Sidebar, Snapshot, Timeslide |
| Layouts version 3 | 2017 | `b:defaultwidgetversion='2' b:layoutsVersion='3'` | version 2               | Contempo, Soho, Emporio, Notable, Essential                       |

<BloggerSource kind="observed" />

## Recognizing a classic theme

A classic theme shows itself in its first lines and its last ones: <BloggerSource kind="observed" />

- `<html>` has `b:version='2'`, or no version at all, and no `b:defaultwidgetversion`. Its widgets render with `data-version='1'`.
- `<html>` has `class='v2'`, which stays on the blog.
- There is no `b:css`, so Blogger links its widget stylesheet.
- `<body>` starts with the class `loading`.
- After `</body>`, the file ends with a `<macro:includable>` and a series of `<b:section-contents>`.

See [Root attributes](./root-attributes.mdx) for the attributes and the combinations of theme and widget versions.

## What differs from layouts version 3

| Feature             | Classic themes                                                       | Layouts version 3                                                              |
| ------------------- | -------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| Widgets             | Version 1: their own markup and data, titles in `<h2 class='title'>` | Version 2, titles from `widget-title`, in `<h3 class='title'>`                 |
| Page data           | `data:blog.pageType`, `data:blog.isMobile`, `data:blog.mobileClass`  | [`data:view`](../data/view.mdx), `data:view.isPost`…                           |
| `data:widgets`      | Not available                                                        | The widgets of the blog, see [`data:widgets`](../data/widgets.mdx#datawidgets) |
| Default markups     | Not confirmed to work                                                | `<b:defaultmarkups>`, `Common` included                                        |
| Mobile              | A mobile template, the `mobile` attribute of widgets, `?m=1`         | Responsive, no mobile template                                                 |
| Sections            | Partly generated by the macro language                               | All written in `<body>`                                                        |
| `<b:template-skin>` | Column widths with `<b:variable>`, and CSS for the blog too          | `body#layout` CSS                                                              |
| Theme Designer      | An "Adjust widths" pane; a `length` gets a form only in a `<Group>`  | Every visible `length` gets a slider                                           |
| Skin output         | The declaration comment stays in `page-skin-1`                       | The comment is removed                                                         |
| Theme script        | Inline scripts                                                       | `<b:template-script>`                                                          |
| Navbar              | The `Navbar` widget at the top of every page                         | None                                                                           |

<BloggerSource kind="observed" />

The logic tags and the expressions belong to the platform, not to a generation: `<b:elseif>`, `<b:switch>`, `<b:with>` and `<b:eval>` came in 2015, and lambdas in 2016, for every theme. <BloggerSource kind="official" /> The classic themes of Blogger use `in` with [lists in braces](../expressions/values.mdx#lists-in-braces), `<b:attr>` and `data:view` in their widgets, which shows that these work with version 1 widgets. Whether every feature works in layouts version 1 themes is not confirmed. <BloggerSource kind="observed" />

## Layouts version 1

A theme with no version attribute is a layouts version 1 theme. Its widgets are version 1, the `mobile` attribute of widgets applies, and `<b:template-skin>` is not allowed. Blogger has shipped no version 1 theme since 2010. <BloggerSource kind="observed" />

## The macro language

Layouts version 2 themes build some of their sections with a small macro language: a block of sections is declared once in `<macro:includable>`, then placed several times with `<macro:include>`, each time with its own parameters. Blogger expands it into ordinary sections, which render like sections written in `<body>`. Google never documented it. <BloggerSource kind="observed" />

The `macro:` and `mexpr:` prefixes are never declared with an `xmlns`. Blogger accepts them, a strict XML parser does not.

### `<macro:includable>`

The block, a direct child of `<html>`, after `</body>`.

| Attribute | Required | Value  | Description                                              |
| --------- | -------- | ------ | -------------------------------------------------------- |
| `id`      | Yes      | a name | The name that `<macro:include>` calls                    |
| `var`     | Yes      | a name | The name of the parameters inside, read as `data:NAME.x` |

<BloggerSource kind="observed" />

This one makes a row of one to three sections, and an optional section under them:

```xml
<macro:includable id='row' var='cell'>
  <macro:if cond='data:cell.count == 0'>
  <macro:else/>
    <div mexpr:class='"row row-" + data:cell.count'>
      <b:section mexpr:class='data:cell.kind' mexpr:id='data:cell.prefix + "-a"'/>
      <macro:if cond='data:cell.count &gt;= 2'>
        <b:section mexpr:class='data:cell.kind' mexpr:id='data:cell.prefix + "-b"'/>
      </macro:if>
      <macro:if cond='data:cell.count &gt;= 3'>
        <b:section mexpr:class='data:cell.kind' mexpr:id='data:cell.prefix + "-c"'/>
      </macro:if>
    </div>
    <macro:if cond='data:cell.withBottom'>
      <b:section mexpr:class='data:cell.kind' mexpr:id='data:cell.prefix + "-bottom"' showaddelement='no'/>
    </macro:if>
  </macro:if>
</macro:includable>
```

Blogger's own classic themes declare one such block, `sections`, with the parameter name `col`. It makes a first section `PREFIX-1`, then from two columns a table of sections `PREFIX-2-1` to `PREFIX-2-4`, and a last section `PREFIX-3` when asked.

### `<macro:include>` and `<macro:param>`

`<macro:include>` places the block in `<body>`, where the sections must appear. Each `<macro:param>` gives one parameter. <BloggerSource kind="observed" />

| Element           | Attribute | Required | Description                          |
| ----------------- | --------- | -------- | ------------------------------------ |
| `<macro:include>` | `id`      | Yes      | A name for this use of the block     |
| `<macro:include>` | `name`    | Yes      | The `id` of the `<macro:includable>` |
| `<macro:param>`   | `default` | Yes      | The value, always written as text    |
| `<macro:param>`   | `name`    | Yes      | The name of the parameter            |

```xml
<macro:include id='footer-row' name='row'>
  <macro:param default='3' name='count'/>
  <macro:param default='footer' name='prefix'/>
  <macro:param default='foot' name='kind'/>
  <macro:param default='false' name='withBottom'/>
</macro:include>
```

With `count` set to `0`, the block makes no section at all: Blogger's themes use this for an empty left column.

### `<macro:if>` and `<macro:else>`

A condition of the macro language, evaluated when the sections are built. `cond` is an expression on the parameters, with comparisons such as `data:cell.count == 0` and `data:cell.count &gt;= 2`, where `>` is escaped as Blogger's themes do. `<macro:else/>` is a self-closed separator, like [`<b:else/>`](../tags/conditionals.mdx). <BloggerSource kind="observed" />

### `mexpr:`

The `expr:` of the macro language: an attribute computed from the parameters when the sections are built. Blogger's themes use it for the `id` and `class` of `<b:section>`, and for the `class` of HTML elements around them. It is how each generated section gets its own id, since the `id` of a section is read when saving and can not be an `expr:`. <BloggerSource kind="observed" />

### `<b:section-contents>`

The generated sections are not in the `<body>` of the file, so their widgets can not be either. Blogger keeps them at the end of the file, after the `<macro:includable>`, in one `<b:section-contents>` per section, with the `id` of the section: <BloggerSource kind="observed" />

```xml
<b:section-contents id='footer-a'>
  <b:widget id='Text1' locked='false' title='About' type='Text'>
    …
  </b:widget>
</b:section-contents><b:section-contents id='footer-b'/><b:section-contents id='footer-c'/></html>
```

- A `<b:section-contents>` contains only `<b:widget>` elements, and is self-closed for a section without widgets.
- Blogger writes these elements itself when the widgets change; a theme author only reads them.
- The ids in Blogger's classic themes are `sidebar-right-1`, `sidebar-right-2-1`, `sidebar-right-2-2`, `sidebar-right-3`, `footer-1`, `footer-2-1` and `footer-2-2`.

### Rendered

The sections render like any other. They have no `name`, since the block gives none, and an empty one gets the class `no-items`: <BloggerSource kind="observed" />

```html title="Rendered"
<div class='row row-3'>
<div class='foot section' id='footer-a'><div class='widget Text' data-version='1' id='Text1'>
…
</div></div>
<div class='foot no-items section' id='footer-b'></div>
<div class='foot no-items section' id='footer-c'></div>
</div>
```

## Version 1 widgets

Version 1 widgets have their own markup and data. Their `main` includable writes the title itself, in an `<h2 class='title'>`, and ends with `quickedit`, the edit icon shown to the blog admin: <BloggerSource kind="observed" />

```xml {4,9}
<b:widget id='Text1' locked='false' title='About' type='Text'>
  <b:includable id='main'>
    <b:if cond='data:title != ""'>
      <h2 class='title'><data:title/></h2>
    </b:if>
    <div class='widget-content'>
      <data:content/>
    </div>
    <b:include name='quickedit'/>
  </b:includable>
</b:widget>
```

The Blog widget of the classic themes names its data `top`, `<b:includable id='main' var='top'>`, tests the page with `data:blog.pageType`, and has a `mobile-main` includable for the mobile template. It groups the posts of a day by printing the opening and closing `<div>` tags as escaped text, `&lt;div class="date-outer"&gt;`, since a `<b:if>` can not hold an open tag alone. The data of each version 1 widget is on its [widget type](../widget-types/index.mdx) page. <BloggerSource kind="observed" />

## The mobile template

In 2011 Blogger let custom themes serve their own mobile view, chosen in the dashboard as the "Custom" mobile template. Mobile browsers get it. <BloggerSource kind="official" /> `?m=1` in the URL asks for it. <BloggerSource kind="observed" />

- The `mobile` attribute of `<b:widget>` decides which widgets the mobile view shows: `yes`, `no`, `only` or `default`. With `default`, only the Header, Blog, Profile, PageList, AdSense and Attribution widgets are shown. <BloggerSource kind="official" /> In a version 3 theme, `mobile` is still read in part: `mobile='only'` hides the widget on the desktop page, and on `?m=1` too, while `yes` and `no` show it on both. Blogger keeps the attribute when it stores the theme, see [`mobile`](../layout/widgets.mdx#mobile). <BloggerSource kind="observed" />
- `data:blog.isMobile` is true in the mobile view.
- `data:blog.mobileClass` is ` mobile` in the mobile view, for the class of `<body>`.

```xml
<b:widget id='Label1' locked='false' mobile='yes' title='Topics' type='Label'>…</b:widget>
```

A classic theme chooses its viewport from the same flag:

```xml
<meta expr:content='data:blog.isMobile ? "width=device-width, initial-scale=1" : "width=1100"' name='viewport'/>
```

Layouts version 3 themes are responsive and have no mobile template. See [data:view](../data/view.mdx) for what `?m=1` gives there.

## The loading class

Classic themes render `<body>` with the class `loading`, plus ` mobile` in the mobile view, and remove `loading` with a short script at the end of `<body>`. Their CSS can style the page while it loads. Google recommends this `<body>` for custom mobile templates, so that the CSS can target `.mobile`: <BloggerSource kind="official" />

<CodeTabs>

```xml title="theme.xml"
<body expr:class='"loading" + data:blog.mobileClass'>
  …
  <script>
    setTimeout(function () {
      document.body.classList.remove('loading');
    }, 10);
  </script>
</body>
```

```html title="Rendered in the mobile view"
<body class='loading mobile'>
```

</CodeTabs>

## The Navbar

Classic themes have a `Navbar` widget, alone and locked in the first section, `navbar`, with `maxwidgets='1'`. Its `main` includable is escaped script text written by Blogger, with the id of the blog, which loads the Blogger bar in an iframe at the top of the page. Layouts version 3 themes dropped it, and its "Report Abuse" link moved to the `ReportAbuse` widget. See [Navbar](../widget-types/navbar.mdx). <BloggerSource kind="observed" />

## The rest of a classic theme

**The skin.** `<b:skin>` has no `version`. It starts with a header comment naming the theme, then a "Variable definitions" comment, which stays in the rendered page. `url` and `string` variables, rare in layouts version 3, are common. See [Theme Designer](../styles/theme-designer.mdx).

**The template skin.** It declares the column widths with `<b:variable>` and holds CSS for the blog as well as for the Layout editor. See [Skin](../styles/skin.mdx#bvariable-in-classic-themes).

**The head.** The viewport depends on `data:blog.isMobile`, `all-head-content` comes before the `<title>`, the title is `<data:blog.pageTitle/>`, and `google-analytics` is included after the skins.

**The sections.** Besides the generated ones, a classic theme of Blogger has fixed sections: <BloggerSource kind="observed" />

| `id`                | `class`  | Holds                              |
| ------------------- | -------- | ---------------------------------- |
| `navbar`            | `navbar` | The Navbar, `maxwidgets='1'`       |
| `header`            | `header` | The Header, `maxwidgets='1'`       |
| `crosscol`          | `tabs`   | A full-width row, `maxwidgets='1'` |
| `crosscol-overflow` | `tabs`   | A second full-width row            |
| `main`              | `main`   | The Blog widget                    |
| `footer-3`          | `foot`   | The Attribution widget             |

They use `showaddelement='yes'` and `showaddelement='no'`, where layouts version 3 themes write `true` and `false`.

## Dynamic Views

Dynamic Views themes are layouts version 2 themes with `b:dynamicViews='true'`. The page is a JavaScript application: Blogger does not render the markup of their widgets. The view, `classic`, `flipcard`, `magazine`, `mosaic`, `sidebar`, `snapshot` or `timeslide`, comes from the `blitzview` skin variable or from the `?view=` parameter of the URL, in `data:blog.view`. The head loads `data:blog.dynamicViewsScriptSrc + "/js/common.js"` and has `<meta content='dynamic' name='blogger-template'/>`. There are two sections, `main` and `sidebar-right-1`. <BloggerSource kind="observed" />

Every Blogger blog has a theme, and the theme is a single XML file. That file decides the HTML of every page of the blog: the homepage, each post, the label and search pages, the archive and the 404 page. It also holds the CSS, the areas where widgets can be placed, the widgets themselves with their settings, and the markup each widget renders.

Blogger keeps the file and renders it again for every visit. It reads the theme together with the data of the requested page (the blog, its posts, comments and widgets), runs the logic written in the theme, and sends plain HTML to the browser.

## A first look

This is the part of a theme that lists posts. The posts come from a Blog widget, and the theme writes the markup of each one. Next to it, what Blogger sends on the homepage of a blog with two posts:

<CodeTabs>

```xml title="theme.xml"
<b:section class='posts' id='main' maxwidgets='1' name='Posts' showaddelement='no'>
  <b:widget id='Blog1' locked='true' title='Blog Posts' type='Blog' version='2' visible='true'>
    <b:includable id='main'>
      <b:loop values='data:posts' var='post'>
        <article class='card'>
          <h2><a expr:href='data:post.url'><data:post.title/></a></h2>
          <p><data:post.snippets.short/></p>
        </article>
      </b:loop>
    </b:includable>
  </b:widget>
</b:section>
```

```html title="Rendered"
<div class='posts section' id='main' name='Posts'><div class='widget Blog' data-version='2' id='Blog1'>
  <article class='card'>
    <h2><a href='https://example.blogspot.com/2026/10/autumn-notes.html'>Autumn notes</a></h2>
    <p>The leaves came down early this year, and the garden needs a plan…</p>
  </article>
  <article class='card'>
    <h2><a href='https://example.blogspot.com/2026/09/first-post.html'>First post</a></h2>
    <p>Welcome to the blog. Here is what to expect from the next months…</p>
  </article>
</div></div>
```

</CodeTabs>

Three things in the theme are not HTML, and they make the whole language:

| Syntax                 | Example                                           | What it does                                                                         |
| ---------------------- | ------------------------------------------------- | ------------------------------------------------------------------------------------ |
| `b:` elements          | `<b:section>`, `<b:widget>`, `<b:loop>`, `<b:if>` | Structure the page and add logic. Blogger replaces them with their output            |
| `data:` tags and paths | `<data:post.title/>`, `data:posts`                | Read the data of the page: write a value, or pass it to a tag                        |
| `expr:` attributes     | `expr:href='data:post.url'`                       | Compute the value of an HTML attribute from an [expression](./expressions/index.mdx) |

Everything else is ordinary HTML, written as XML: every element closed, every attribute quoted.

## Reading the guide

Read the four Basics pages in order. They set up the vocabulary the rest of the guide uses: section, widget, includable, page type, saving, and the [Glossary](./basics/glossary.mdx) keeps it at hand. After that, each page stands on its own: an Intermediate or Advanced page names the pages it builds on under its title, after **Read first**.

Pages about a tag share one plan: what the tag does, a first example, how it works, a table of its attributes and a section for each, then patterns and edge cases. The rendered HTML is shown next to the theme when it helps.

The guide describes themes of the current generation: layouts version 3 with version 2 widgets, the generation of Contempo, Soho, Emporio, Notable and Essential, and of most themes written since. Where an older theme behaves differently, the page says so, and [Classic themes](./reference/classic-themes.mdx) covers the older generations.

### How examples are written

The examples follow one style, close to the way Blogger keeps a theme after saving it:

- attributes sorted by name and quoted with single quotes, as Blogger stores them: `<b:include data='post' name='postMeta'/>`;
- elements with nothing inside them closed in place, as Blogger stores them: `<b:else/>`, `<b:section id='footer'/>`;
- every expression on one line, with `"` for strings inside the single quotes: `cond='data:view.type == "item"'`. Blogger stores that `"` as `&quot;`, and `>` as `&gt;`; both spellings are the same XML;
- `and` and `or` rather than `&amp;&amp;` and `||`, and `&lt;` for the `<` operator, which XML does not allow in an attribute.

The last two are the guide's choices. Blogger stores expressions exactly as written, apart from that escaping: `&amp;&amp;`, `eq` or extra spaces stay as you type them. [Saving a theme](./basics/saving.mdx#how-blogger-rewrites-the-theme) lists the rewrites Blogger makes.
